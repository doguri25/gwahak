# 우리 학교 건강탐정단
## 애니메이션 본편 확장판 v1.2.0 · 만든이: 도구리

승인한 애니메이션 인물·교실 그림과 파스텔 UI를 그대로 사용하면서, **본편 1~6장과 에필로그를 끝까지 연결**한 웹 게임입니다. 이미지 위의 메뉴·대사·선택지·진도는 실제로 조작하는 HTML 요소입니다. 이번 빌드는 본편 확장판이며, Firebase 온라인 학급 기능까지 출시 완료한 버전을 뜻하지 않습니다.

## 바로 실행하기

`index.html` 하나에 코드·대본·그림이 포함되어 있습니다. 외부 폰트나 런타임 패키지를 받지 않습니다. HTML 실행을 지원하는 브라우저에서 엽니다. 모바일 파일 미리보기에서 실행되지 않는 경우에는 정적 웹 호스팅에 게시한 주소로 접속해야 합니다. 이번 작업에서는 웹주소를 실제로 배포하지 않았습니다.

처음 시작하면 새 게임 상태입니다. 테스트에서 만든 완료 기록이나 가상 학생 점수를 실행 파일에 미리 넣지 않았습니다.

## 이전 진도 이어하기

기존 파일에서 **설정 → 저장 내보내기**로 JSON을 보관하고, 새 파일에서 **설정 → 가져오기**를 사용합니다. 1장을 마쳤다면 이어하기 버튼으로 2장에 들어갑니다. 다른 장소나 활동에서 멈췄다면 해당 위치부터 복원합니다.

v0.1.0, v0.1.1, v0.1.2, v1.0.0, v1.1.0의 schemaVersion=1 기록을 읽는 호환 코드를 유지했습니다. v1.1.0 저장 파일의 실제 가져오기와 2장 연결을 브라우저 테스트에서 확인했습니다. 같은 웹 출처에서 저장 공간을 사용할 수 있으면 기존 저장을 읽지만, 파일 이름·브라우저·도메인을 바꿨을 때 자동 이전을 보장하지 않습니다. 공용 태블릿에서 학생이 바뀔 때는 먼저 저장 파일을 보관한 뒤 기기 기록을 지우세요.

## 구현한 콘텐츠

| 항목 | 수량 |
|---|---:|
| 본편 | 6장 / 필수 에피소드 18개 |
| 시작과 마무리 | 프롤로그 1개 / 에필로그 1개 |
| 선택 의뢰 | 12개 |
| 인물 이야기 | 6개 |
| 전체 이야기 항목 | 38개 |
| 대화·선택·조사·활동·보상·종료 노드 | 588개 |
| 조사 단서 | 68개 |
| 해결 활동 | 37개 / 조작 체계 8종 |
| 컬렉션 | 72개 |
| 장별 도전 연습 | 6개 묶음 × 10문항 = 60문항 |

위 수량은 콘텐츠 파일을 검사한 결과입니다. **학생 기준 플레이 시간은 아직 실측하지 않았습니다.** 노드에는 분기·보상·조사 진입 등이 포함되므로 588개를 모두 서로 다른 대사라고 세지 않습니다. PRD의 목표 시간이나 정식 전체 이미지 수량을 달성했다고 표시하지 않습니다.

| 장 | 이야기와 활동 |
|---|---|
| 1. 축제 준비실의 첫 의뢰 | 감기·독감 자료 비교, 사실과 추측, 친구에게 필요한 도움 |
| 2. 보이지 않는 이동 | 가상 표식의 이동 순서, 생활 속 예방 시점, 모형과 실제의 구분 |
| 3. 같은 교실, 다른 선택 | 공기 관리 자료, 여러 예방 행동 조합, 방송 안내문 만들기 |
| 4. 점심시간의 작은 단서 | 음식·물 자료 판단, 개인 식기·용품 구분, 필요한 도움 요청 |
| 5. 예방은 한 가지가 아니야 | 가상 관찰 전후 비교, 손 씻을 때 살펴볼 부위, 생활 계획 |
| 6. 모두의 하루를 지키는 작전 | 학교 준비 상황 점검, 역할 연결, 근거가 담긴 최종 안내문 |

이야기 지도에서 1~6장 탭을 고릅니다. 앞선 본편을 마치면 다음 에피소드가 열리며, 선택 의뢰를 모두 마쳐야 본편이 열리는 구조는 아닙니다. 완료한 장면을 다시 읽을 수도 있습니다.

## 조작 방법

대화는 ‘다음 이야기’와 선택지로 진행합니다. 조사 번호나 단서 이름을 누르면 가운데 모달이 열립니다. **수첩에 기록하고 닫기**를 눌러야 단서가 수집되며, 닫기만 누르면 수집되지 않습니다. 기록한 단서를 다시 읽어도 중복 보상을 받지 않습니다.

새 활동은 드래그 없이 터치로 조작합니다.

| 체계 | 조작 |
|---|---|
| 자료 비교 / 자료 분류 | 답을 고르고 ‘선택 확인’. 잘못 고르면 해설을 읽고 다시 선택 |
| 연결 | 왼쪽 상황을 고른 뒤 오른쪽의 관련 내용 선택 |
| 순서 재구성 | 카드를 차례로 누르기. 선택한 카드를 다시 누르거나 빼기 버튼으로 수정 |
| 예방 작전 | 여러 행동 카드를 조합해 필요한 조건 충족. 안전한 대안 조합 허용 |
| 가상 관찰 | 자료 카드를 모두 읽고, 그 자료로 알 수 있는 내용을 판단 |
| 손 씻기 점검 | 여섯 부위 설명을 읽고 생활 속 손 씻기 상황 확인. 실제 실천을 기록하지 않음 |
| 안내문 만들기 | 각 부분의 문장을 고르고 안내문 완성. 여러 적절한 표현 허용 |

6장 안내문은 **수첩 → 마지막 안내문** 또는 **교사용 안내 → 마지막 안내문**에서 다시 읽거나 TXT로 보관합니다. 선택한 문장도 저장 파일에 포함됩니다.

## 도감과 수집

감염병 도감 12개, 개념 카드 24개, 배지 16개, 조사 기록 12개, 특별 장면 8개입니다. 도감·모은 기록·종류별 필터가 있고 잠긴 기록에는 획득 조건이 나옵니다. 질환 자료는 메인 화면의 초록 버튼에서 미리 읽을 수 있습니다. 미리 읽기 자체는 획득 조건을 대신하지 않습니다.

도감에는 감기, 독감, 수족구병, 유행 각결막염, 코로나19, 결핵, 식중독, 노로바이러스 감염증, 파상풍, 무좀, 수두, 유행성이하선염을 다룹니다. 식중독은 여러 원인이 있는 넓은 범주로 설명하며, 모든 항목을 동일한 전파 방식으로 묶지 않습니다.

## 도전 기록과 교사용 메뉴의 범위

장별 연습은 각각 10문항·1,000점입니다. 읽기 시간·수집량·반복 횟수 보너스는 없습니다. 제출 후 해설을 제공하고 같은 장 안에서 닉네임별 최고 기록을 표시합니다. 서로 다른 장의 점수는 섞지 않으며 동점은 공동 순위입니다. 중단한 회차는 같은 문항에서 이어갑니다.

**현재는 기기 안에서 계산하는 연습입니다.** Firebase, 교사 인증, 학급 입장 코드, 서버 채점, 기기 간 동기화, 온라인 학급 랭킹은 연결하지 않았습니다. 교사용 메뉴는 현재 기기의 진도·완료 항목·내보내기와 운영 안내이며, 실제 학급 전체 학생을 관리하는 화면이 아닙니다. 클라이언트 저장 기록은 조작할 수 있으므로 공식 평가용 검증 점수로 사용하지 않습니다.

## 그림과 접근성

v1.1.0의 승인한 애니메이션 그림 데이터를 변경하지 않았습니다. 기존 얼굴로 바꿔 그리지 않았으며, 서로 다른 새 표정·장소 그림을 제작했다고 주장하지 않습니다. 대화 화면은 승인된 교실 그림을 공통으로 사용하고, 장소 이름·대사·활동이 달라집니다. 조사 화면에는 교실·준비실·보건실 학습용 배치도를 재사용합니다.

기본 글자 설정 115%, 조절 범위 100~180%입니다. 세로 화면과 큰 글자에서는 필요한 영역을 세로 스크롤합니다. 소리 없이 진행할 수 있으며 음성 읽기는 기기의 한국어 음성 지원이 필요합니다. 음성을 녹음하거나 전송하지 않습니다.

## 내용 검토

공식 기관의 일반 예방교육 자료를 확인하고 새 대본·가상 자료로 구성했습니다. 출처는 앱과 `docs/CONTENT_SOURCES.md`에 있습니다. 외부 보건 전문가의 내용 검토, 실제 태블릿 수업 검수, 학생 기준 플레이 시간 측정은 미실시입니다. 실제 진단·복약·소독 작업·배양 실험·접종 일정·등교 여부 판단은 제공하지 않습니다. 실제 학생의 건강정보·접종 기록·사진을 입력받지 않습니다.

## 개발과 배포 파일

`index.html`은 실행용이고, `src/app.ts`, `src/content.json`, CSS 파일은 편집용 원본입니다. `src/full.ts`에는 2~6장용 UI·활동 로직의 재생성용 조각이 있습니다. 소스 변경 후 실행 파일을 다시 만듭니다.

```sh
python3 tools/build.py
python3 tools/validate_content.py
node tools/prepare-deploy.mjs
```

Python 3.10+, TypeScript 컴파일러가 필요합니다. 콘텐츠 검증에는 Pillow가 필요합니다. `tools/expand_content.py`는 기존 `tools/content_v110.json`에 확장 대본을 붙여 콘텐츠를 재생성합니다. `tools/patch_full.py`는 기존 엔진 템플릿 `tools/app_v110.ts`와 `src/full.ts`로 엔진을 재생성하므로, 직접 수정한 `src/app.ts`에 무심코 실행하여 변경을 덮어쓰지 않도록 주의하세요.

`dist/index.html`은 배포용 사본입니다. Vercel 설정은 미리 빌드된 HTML을 정적 출력으로 복사합니다. GitHub Pages에는 저장소의 `index.html`을 정적 페이지로 게시할 수 있습니다. 이번 작업에서는 저장소 생성·푸시·온라인 배포·결제 설정 변경을 수행하지 않았습니다.

## 테스트

```sh
python3 tests/qa_full.py
python3 tests/qa_full_layout_save.py
```

Playwright와 시스템 Chromium이 필요합니다. 이 작업 환경에서는 실제 URL 이동이 관리자 정책으로 차단되어 HTML을 `about:blank`에 마운트하고 Storage 테스트 대역을 사용했습니다. 진행·조작·저장 로직을 확인한 것이지 실제 기기의 브라우저 저장소, 네트워크 배포, iOS Safari, Firebase 검증을 대신하지 않습니다. 자세한 결과는 `docs/QA.md`와 JSON 보고서에 있습니다. 테스트 스크린샷은 자동화 테스트 기록이지 실제 학생 자료가 아닙니다.
